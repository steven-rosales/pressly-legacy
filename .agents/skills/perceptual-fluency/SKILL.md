---
name: perceptual-fluency
description: >-
  Write markdown for high human legibility in IDEs, docs, lectures, explanations, specs, and agent notes. Use to avoid md files being dense, hard to scan, structurally unclear, or likely to overload human readers. Optimize for maximal visible structure, short chunks, nearby constraints, examples after rules, and low effort.
---

Motivation: Agents write text in markdown that is not easily readable to the human eye. They also write text that is too large for the purpose of the writing (e.g., a simple test guide file that is 1000 lines when it should 10% of that).

Make markdown easy to scan.

Rules:

- Use clear heading and stable names.
- Keep paragraphs short.
- Prefer shallow lists.
- Number procedures.
- Put one idea per line when useful.
- Fence commands and code.
- Keep constraints beside the rule.
- Place examples after rules.
- Use explicit contrasts.
- Remove filler.
- Preserve technical meaning.
- Keep text size proportional to the necessary information from the purpose of the text.

Use perceptual fluency and cognitive load: readers scan through fixations, saccades, and regressions; structure reduces effort.

Output:

- Purpose visible in 3 seconds.
- Sections visible in 3 seconds.
- Next step visible.
- Text or code usable without rereading.
